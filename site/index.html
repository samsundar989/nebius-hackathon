    How it works

    Four NVIDIA Nemotron models on Nebius Token Factory, each with one job. The gate runs separately, offline, and decides.

    1. ReproduceDocker or Nebius SandboxesBuild the project with sanitizers and confirm the crash.
    2. DiagnoseNemotron 3 UltraFind the root cause and propose up to four fixes.
    3. Patch4 × Nemotron 3.5 LightningEach writes one patch on its own copy. None sees the tests.
    4. AttackNemotron 3 SuperWrites inputs meant to break each surviving patch.
    5. GateSanitizers, tests, re-fuzzingShip with the evidence, or refuse and say why.

      Limits
      • The old OSS-Fuzz bugs were fixed upstream years ago, so the models may have seen those fixes in training. The still-open bugs above are the clean test.
      • The gate proves the reported crash is gone and that nothing it tried causes a new sanitizer report. It can't prove a fix correct for every input, which is why a person reviews each fix before it is sent.
      • Without project tests, a verified patch is labelled "verified, needs human review".
      • Leak results come from Juliet, which is synthetic; the OSS-Fuzz set has no leak cases.
      • Nebius Sandboxes runs Juliet and bring-your-own projects; the OSS-Fuzz images run on local Docker.
