## Root cause (planner)

In decToString (decNumber.c), scientific notation mode (eng=0) incorrectly calculates pre = e + 1 for positive exponents, where e is the decimal exponent. This causes the coefficient layout loop to write pre digits (padding with zeros after exhausting significant digits), producing up to e+1 output characters. The caller jvp_literal_number_literal (jv.c) allocates only digits + 14 bytes per the library's documented requirement, which is insufficient when e is large (up to 999999999 per library comments). The heap overflow occurs when writing the NUL terminator past the allocated buffer.
