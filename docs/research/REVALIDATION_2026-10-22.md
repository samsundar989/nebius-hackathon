# Re-validation — 2026-10-22 (8 days to deadline)

Three research passes on Oct 22: (1) competition delta since Oct 13, (2) competitor field refresh with a hunt for Leakproof-like entries, (3) feasibility inputs for an 8-day finish. Condensed here; the raw reports live in the Cowork session.

## Verdict

**Leakproof stays. Descoped, not replaced.** Reasons:
1. The memory-safety lane is still essentially empty. One direct competitor (SegSense, below) covers a single-file-C subset with a weak gate. Nobody does multi-file C/C++ projects, CUDA/compute-sanitizer, fuzz re-verification, Juliet or ARVO numbers.
2. E0 already works (Token Factory client, Docker Runner with branching, parsers, Juliet 58/60, 3 ARVO cases, a Lightning fix). Any new idea restarts from zero with 8 days.
3. The judges' Oct 20 session rewards exactly what Leakproof produces: a real problem, the "aha" in the first 30 s of the demo (a real crash → verified fix), which model does what, and **documented limitations**.
4. The field's house style for Coding-track Python repair (planner + parallel workers in forked sandboxes + independent gate + receipts) is now common — ~9 submission-complete entries, maybe 15 by Oct 30. Our architecture alone is not the differentiator; the domain (compiled code, sanitizers), real projects (ARVO), and the stronger gate are.

## 2. Competitor field (Oct 22)
- **SegSense — "Agentic Debugger for C Memory Bugs"** (devpost.com/software/segsense-agentic-debugger-for-c-memory-bugs; github.com/Blop77/SegSense). 4-person team, started Oct 10. Loop: compile one `.c` file with ASan/UBSan, parse report, Nemotron 3 Nano triages, Tavily fetches MITRE CWE + SEI CERT references, Nemotron 3 Ultra rewrites the file, rebuild+rerun until clean. Accept rule: builds + ASan silent + stdout unchanged on one input. Eval: 8 bundled bugs "fixed first try" + one cJSON CVE compared on 116 inputs. Hosted demo (Render) + 2:35 video + CI. **Gaps:** single file only, no C++, no multi-file builds, no CUDA, no Sandboxes, no PRs, no Juliet/ARVO, no re-fuzz, no safe-fix check, Valgrind/TSan "planned". ## 3. Feasibility inputs
### ARVO (real, Docker-reproducible OSS-Fuzz bugs)
- arvo.db v3.0.0: 6,138 rows, all reproduced/patch_located; 3,442 ASan heap-class (HBO/UAF/double-free/invalid-free); **zero leak cases** (confirmed from the DB); `language` column unreliable.
- Image size pattern (Docker Hub `full_size`, compressed): cases built on ~2023+ base images are **570–690 MB**; older ones 1.2–1.8 GB (lua, sudo, libdwarf, libyaml, zstd, flac, md4c 42493685 — avoid for the batch).
- Tier-1 shortlist (26 cases, one per developer fix, C projects with tests): see `cases/arvo/shortlist_2026-10-22.json`. Projects: jq (make check), mosquitto (cunit + python tests), oniguruma, libplist, miniz, md4c (run-tests.sh), quickjs (make test), libssh2, libzip (CTest), libical (CTest), pcre2 (RunTest), lz4 (make -C tests), libbpf (no unit tests → fuzzer-on-corpus only), h3 (CTest). Builds 1–4 min each.
- Query to extend: `SELECT localId, project, crash_type, fuzz_target, fix_commit, patch_url FROM arvo WHERE sanitizer='asan' AND submodule_bug=0 AND (crash_type LIKE 'Heap-buffer-overflow%' OR crash_type LIKE 'Heap-use-after-free%' OR crash_type LIKE 'Heap-double-free%' OR crash_type LIKE 'Invalid-free%') AND project IN (...) GROUP BY project, fix_commit;` Size check: `curl -s https://hub.docker.com/v2/repositories/n132/arvo/tags/<id>-vul | jq .full_size`.
### Leak corpus
- OSS-Fuzz issue tracker needs Google login for testcases; `oss-fuzz-vulns` has no leaks (not security-flagged). Not a one-day path.
- Cheapest credible leak story: **Juliet CWE-401** as the quantitative leak set (hundreds of variants; we detect 58/60 with `-O0` + `use_stacks=0`) + optional 3–5 "fix memory leak" commits mined from jq/libyaml/cJSON history as case studies (`git log -i --grep=leak -- '*.c'`, parent commit = vul, test added in the fix = reproducer; ~50% usable) + ARVO heap-class as the real-world quantitative set. README states plainly that ARVO contains no leak cases.
- 30-min experiment: run ARVO PoCs/corpora with `ASAN_OPTIONS=detect_leaks=1` to harvest incidental real leaks (no ground-truth fix, but real).
